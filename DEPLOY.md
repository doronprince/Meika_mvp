# Putting Meika online

The Flutter web app goes on **GitHub Pages**. The API and database cannot:
Pages serves static files only, and Meika needs a running FastAPI process
and a PostgreSQL database. So the backend goes on **Render** and the
database on **Neon** (Render's own free PostgreSQL expires after 30 days;
Neon's does not).

Everything in the repo is ready. What's left needs your own accounts.
Budget about 20 minutes.

```
   Browser ──► GitHub Pages (Flutter web)  ──HTTPS──►  Render (FastAPI)  ──►  Neon (PostgreSQL)
               doronlintonprince.me/Meika_mvp/         meika-api.onrender.com
```

---

## 1. Database: Neon (5 minutes)

1. Sign up at <https://neon.tech> and create a project (pick a region near
   you, e.g. Singapore).
2. Copy the connection string. It looks like:
   `postgresql://user:password@ep-something.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
3. Keep it for step 2. The app rewrites it for asyncpg and enables TLS by
   itself (`normalize_database_url` in `backend/app/core/config.py`), so
   paste it exactly as Neon gives it — `sslmode`, `channel_binding` and all.
   A pooled host (the `-pooler` one Neon shows by default) also works: the
   app turns off asyncpg's statement caches for pooled hosts, without which
   PgBouncer makes queries fail intermittently with "prepared statement does
   not exist".

The schema is created on first boot by `start.sh`, so there is nothing to
run by hand. To prepare the database before deploying, point the backend at
it locally instead:

```bash
cd backend
DATABASE_URL="<your Neon string>" .venv/Scripts/python -m alembic upgrade head
DATABASE_URL="<your Neon string>" .venv/Scripts/python -m scripts.seed_dev_user
```

## 2. API: Render (10 minutes)

1. Sign up at <https://render.com> with your GitHub account.
2. **New → Blueprint**, pick `doronprince/Meika_mvp`. Render reads
   [`render.yaml`](render.yaml) and proposes the `meika-api` service.
3. Set the environment variables it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `CORS_ORIGINS` | `https://doronlintonprince.me` (no trailing slash) |
   | `SERPAPI_API_KEY` | your key, or leave empty |
   | `GEMINI_API_KEY` | your key, or leave empty |

   `JWT_SECRET_KEY` is generated by Render. `SEED_DEMO_DATA` is `true`, so
   the demo accounts are created on first boot; set it to `false` if you'd
   rather have registration only.
4. Deploy. The container runs migrations, seeds the demo data, then serves.
5. Check it: `https://<your-service>.onrender.com/api/v1/health` should
   return `{"status":"ok", ... "database":"ok"}`. Interactive API docs are
   at `/docs`.

## 3. Web app: GitHub Pages (5 minutes)

1. Pages is already enabled for this repo with Source: GitHub Actions,
   and HTTPS is enforced. Nothing to do unless you reset it.
2. Repo **Settings → Secrets and variables → Actions → Variables → New**:

   | Variable | Value |
   |---|---|
   | `MEIKA_API_BASE_URL` | `https://<your-service>.onrender.com/api/v1` |
   | `MEIKA_WS_BASE_URL` | `wss://<your-service>.onrender.com/ws` |

   Both must be `https`/`wss`. A browser on an HTTPS page refuses plain
   `http`/`ws` calls, and the app will look broken with only a console error.
3. **Actions → Deploy web app to GitHub Pages → Run workflow** (it also runs
   on every push to `master`).
4. Open `https://doronlintonprince.me/Meika_mvp/` on any device.

## 4. Check it end to end

Sign in with a demo account, or register a fresh one:

- `dev@meika.example` / `MeikaDemo123!` — dashboard, budget, goals, Price-Finder
- `tax@meika.example` / `MeikaTax123!` — 14 months of history, so Foresight has flags to show

Walk the tabs: Dashboard, Price-Finder, Budget, Goals, Foresight (five
modules), Copilot.

## Things that will bite you

- **First request after a pause takes ~50 seconds.** Render's free service
  sleeps when idle. Open the site a minute before a demo, or keep the tab open.
- **CORS must match exactly.** `CORS_ORIGINS` is the origin only —
  `https://doronlintonprince.me` — not the full path to the app. This
  account serves Pages from a custom domain, so it is NOT
  `doronprince.github.io`; HTTPS is enforced on it.
- **Demo passwords are public** once the site is. Don't reuse them anywhere,
  and set `SEED_DEMO_DATA=false` if that bothers you.
- **The free search quota is shared.** SerpApi's free tier is 100 searches a
  month across Price-Finder, the Copilot and claim check. When it runs out,
  Price-Finder falls back to the seeded catalog and claim check reports that
  no evidence could be retrieved — neither invents results.
- **With no `GEMINI_API_KEY`** the Copilot answers from its deterministic
  path, which is grounded in the same computed numbers. Tax questions always
  take that path by design.
- **`GEMINI_MODEL` must name a model your key can serve.** Google retires
  them: `gemini-2.0-flash` now returns 404 "no longer available". The
  default is `gemini-2.5-flash`, which was generally available when this was
  written. The `-latest` aliases point at preview models that returned 503
  under load in testing. On the free tier expect the occasional 503 or a 429
  quota error; the copilot logs it and answers deterministically instead, so
  a demo never breaks on it.
- **Rate limiting is per process** (60 requests/minute, 10 for auth). Fine
  for one free instance; it would need Redis before scaling out.

## Running it locally instead

```bash
python scripts/dev_up.py
```

Starts Postgres in Docker, applies migrations, seeds demo data and serves the
API, then prints the `flutter run` command for the client.
